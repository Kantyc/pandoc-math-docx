# pandoc-math-docx (English)

> 📖 **中文**: [README.md](README.md)

A [Claude Code](https://claude.com/claude-code) skill that generates Microsoft Word documents (`.docx`) containing **native, editable math equations** (OMML format, not images) from Markdown + LaTeX input via [Pandoc](https://pandoc.org/).

## What it does

Convert Markdown with LaTeX math into a Word document where equations are real, editable Word equations:

```
$$\frac{\partial \mathbf{u}}{\partial t} + (\mathbf{u}\cdot\nabla)\mathbf{u} = -\nabla p + \mu \nabla^2 \mathbf{u}$$
```

becomes a native Word equation that you can click into and edit — with correct typography: variables italic, operators upright, stretchy brackets, proper fraction bars, right-aligned equation numbers.

## Why this skill exists

Generating a Word document with properly typeset math is deceptively hard:

1. **Pandoc drops `\tag{}`** — equation numbers vanish. The skill re-inserts them via 3-column borderless tables.
2. **Times New Roman cannot be the math font** — it has no OpenType `MATH` table and no coverage of the Unicode Mathematical Alphanumeric Symbols plane (U+1D400+), where Word transcodes math variables. The skill uses **TeX Gyre Termes Math** — a glyph-level clone of Times with a complete MATH table — so equations look like Times while remaining native and editable.
3. **`<m:nor/>` is a trap** — injecting "normal text" mode to force a font breaks auto-italic, makes brackets italic, and disables the math engine. The skill explicitly avoids this and documents why.
4. **Body fonts need a reference doc** — Chinese in SimSun, English in Times New Roman requires a `--reference-doc` with the right `docDefaults`.

The skill encodes all of this into a repeatable workflow with auto-detected dependencies.

## Formatting produced

| Element | Font | Style |
|---|---|---|
| Chinese body text | SimSun (宋体) | regular |
| English & digits (body) | Times New Roman | regular |
| Math symbols / variables | TeX Gyre Termes Math | italic |
| Operators (`+ − = · ∇ ∂ ∫`) | TeX Gyre Termes Math | upright |
| Sub/superscript labels | TeX Gyre Termes Math | upright (via `\mathrm{}`) |
| Equation numbers `(1)`, `(2)` | Times New Roman | right-aligned |

## Workflow

```bash
# 0. Check & install dependencies (pandoc + TeX Gyre Termes Math + Python packages)
python scripts/ensure-deps.py --install

# 1. Write Markdown source with LaTeX math (e.g., input.md)

# 2. Convert with Pandoc (--mathml is mandatory for native OMML)
pandoc input.md -o output.docx --mathml --reference-doc=reference.docx

# 3. Post-process: equation numbering + table layout + strip <m:nor/>
python scripts/post-process.py output.docx

# 3b. Set the math font to TeX Gyre Termes Math
python scripts/set-mathfont.py output.docx

# 4. Open output.docx in Word/WPS to verify equations
```

## Scripts

| Script | Purpose |
|---|---|
| `scripts/ensure-deps.py` | Detect and install pandoc, the math font, and Python packages |
| `scripts/post-process.py` | Equation numbering (3-column tables), strip `<m:nor/>`, re-zip |
| `scripts/set-mathfont.py` | Set `mathFont` in settings.xml + declare it in fontTable.xml |
| `scripts/docx-to-pdf.ps1` | Word COM export to PDF (for layout checks) |
| `scripts/verify-fonts.py` | Extract per-glyph fonts from a PDF to verify rendering |

## Key technical points

### Why TeX Gyre Termes Math?

Measured with `fontTools`:

| Font | MATH table | U+1D400 coverage | Looks like Times? |
|---|---|---|---|
| Times New Roman | ❌ | ❌ none | — (cannot be a math font) |
| TeX Gyre Termes Math | ✅ | ✅ full | ✅ (glyph clone of Times) |
| STIX Two Math | ✅ | ✅ full | ❌ (redesigned letterforms) |
| XITS Math | ✅ | ✅ full | ❌ (redesigned letterforms) |
| Cambria Math | ✅ | ✅ full | ❌ (Word's default, not Times) |

TeX Gyre Termes Math is built on URW Nimbus Roman No9 L — a direct clone of Times — so its letterforms match Times New Roman while still providing the OpenType MATH table Word requires for stretchy brackets, integrals, and fraction layout.

### Why not force Times New Roman onto math runs?

Injecting `w:rFonts="Times New Roman"` onto `<m:r>` elements only changes the digits (and wrongly italicizes them); variables stay in the math font because Word transcodes them to U+1D400, where Times New Roman has no glyphs. This is a dead end — documented in `SKILL.md` as Pitfall 2.

### PDF export caveat

Word's `ExportAsFixedFormat` (PDF export) has been observed to **drop all equations** when the math font is not Cambria Math — the equation count falls to 0 in the exported PDF, while the on-screen document renders fine. To verify the math font, **open the `.docx` in Word or WPS directly**. If a PDF preview is needed, export via WPS (which preserves non-Cambria math fonts) or fall back to Cambria Math for that document.

## Installation (as a Claude Code skill)

Copy the `pandoc-math-docx/` directory into your Claude Code skills folder:

- **Windows**: `C:\Users\<you>\.claude\skills\pandoc-math-docx\`
- **macOS / Linux**: `~/.claude/skills/pandoc-math-docx/`

The skill auto-triggers when a request mentions "formulas", "equations", "math", "公式", "方程", etc. in the context of a Word/.docx document.

## Requirements

- Windows (the font install and Word COM scripts are Windows-specific; the Pandoc + Python pipeline itself is cross-platform)
- Python 3.8+ with `fonttools` and `pymupdf`
- Pandoc 3.x
- Admin rights (only for installing the math font system-wide; otherwise it falls back to Cambria Math)
